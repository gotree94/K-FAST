## Part A. AI Inference와 NPU 이해 (모듈 1)

### A-1. 학습과 추론의 차이 / 추론 워크로드의 특징
**문제** : "학습(Training)"과 "추론(Inference)"의 차이를 설명하고, 추론 워크로드의 특징 3가지를 서술하시오.

**채점 포인트**
- 학습: 대량 데이터로 가중치 갱신, 순전파+역전파 반복, 고정밀(FP32/BF16) 필요
- 추론: 고정 가중치로 순전파만, 지연시간·처리량·전력효율이 핵심
- 특징 ① 행렬 곱·텐서 축약이 대부분 ② 데이터 재사용성 높음 → SRAM 활용 ③ 반복·실시간 실행 → 지연/처리량 최적화

### A-2. NPU 아키텍처 핵심 요소
**문제** : NPU 성능을 결정하는 구성 요소 4가지 이상과 역할을 쓰고, 온칩 SRAM이 왜 중요한지 설명하시오.

**채점 포인트**
- PE(MAC 배열): 텐서 축약·행렬 곱 고속 수행
- 온칩 SRAM: 가중치·중간 결과 재사용 → 외장 메모리 접근 최소화 → 성능의 핵심
- 외장 메모리(HBM): 모델 전체 저장(예: RNGD HBM3 48GB, 1.5TB/s)
- NoC(내부 네트워크): PE↔SRAM↔메모리 데이터 이동 경로
- PCIe(호스트 인터페이스): CPU와 데이터 교환, IO 병목 지점

### A-3. 컴퓨트 바운드 vs 메모리 바운드
**문제** : 두 개념을 정의하고, LLM 디코드(Decode) 단계가 메모리 바운드인 이유를 서술하시오.

**채점 포인트**
- 컴퓨트 바운드: 연산 유닛이 병목 → 활용률 높음 → 연산 성능 확대가 해법
- 메모리 바운드: 데이터 이동이 병목 → 활용률 낮음 → 대역폭/재사용 개선이 해법
- 디코드: 토큰 1개 생성 시 전체 KV 캐시를 읽어야 하므로 데이터 이동량이 연산량보다 큼 → 메모리 대역폭이 성능 결정

### A-4. 양자화와 정밀도
**문제** : 양자화의 개념과 효과 3가지, 주의점을 서술하고 RNGD의 정밀도별 성능을 쓰시오.

**채점 포인트**
- 개념: FP32 등을 INT8/FP8/INT4 저정밀로 변환
- 효과: ① 연산 속도 증가(저정밀→TOPS 상승) ② 메모리 사용량 감소 ③ 대역폭 절감
- 주의: 정확도 손실 → PTQ/QAT로 보완, 측정 기반 판단
- RNGD: BF16 256TFLOPS / FP8 512TFLOPS / INT8 512TOPS / INT4 1,024TOPS

## Part B. RNGD 및 Software Stack (모듈 2)

### B-1. RNGD 기본 사양
**문제** : RNGD의 주요 사양(아키텍처, 공정, 정밀도별 성능, 메모리, SRAM, 인터페이스, 전력)을 항목별로 서술하시오.

**채점 포인트**
- 아키텍처: TCP(Tensor Contraction Processor), PE 8개
- 공정: TSMC 5nm, 1.0GHz
- 성능: BF16 256TFLOPS / FP8 512TFLOPS / INT8 512TOPS / INT4 1,024TOPS
- 메모리: HBM3 48GB(2스택), 1.5TB/s / 온칩 SRAM 256MB(약 384TB/s)
- 인터페이스: PCIe Gen5 x16, 칩 간 P2P
- 전력: TDP 150W(자료에 따라 180W 표기), 패시브 쿨링·공랭 배포
- 신뢰성: ECC, Secure Boot(RoT), 멀티인스턴스 8개, SR-IOV 8VF

### B-2. Software Stack 계층과 역할 / ENF·FXB 구분
**문제** : 소프트웨어 스택을 "드라이버/펌웨어 → 컴파일러 → 런타임 → LLM 서빙" 계층으로 나누어 역할을 서술하고, ENF와 FXB의 차이를 쓰시오.

**채점 포인트**
- 드라이버/펌웨어: NPU 디바이스 인식, PE 내부 실행 관리(PERT)
- 컴파일러: 그래프 최적화·연산자 융합·메모리/스케줄 최적화 → ENF 생성
- 런타임: ENF 로드·실행, 스케줄링, 메모리 할당, 멀티NPU 관리
- furiosa-llm: LLM 서빙 엔진, vLLM 호환 API, OpenAI 호환 서버, PagedAttention·연속 배치
- ENF: 단일 모델 컴파일 결과물(일반 런타임용) / FXB: furiosa-llm용 컴파일 번들(아키텍처 지문으로 재사용 판정, -tp는 빌드 시 고정, -pp/-dp는 서빙 시 지정)

### B-3. furiosa-llm 핵심 기능
**문제** : furiosa-llm의 핵심 기능 4가지를 쓰고, "연속 배치(Continuous Batching)"가 처리량에 중요한 이유를 설명하시오.

**채점 포인트**
- ① vLLM 호환 API(LLM/LLMEngine/AsyncLLMEngine) ② PagedAttention ③ 연속 배치 ④ HF 허브 연동 + OpenAI 호환 서버 + 스트리밍
- 연속 배치: 요청이 도착하는 대로 배치에 추가/제거해 NPU를 계속 채움 → 요청별 생성 길이가 달라도 메모리·연산을 효율적으로 활용 → 처리량 극대화

### B-4. 멀티카드 구성과 텐서 병렬
**문제** : 70B급 LLM 서빙 시 여러 카드가 필요한 이유와, 텐서 병렬 설정이 빌드 시인지 서빙 시인지를 설명하시오.

**채점 포인트**
- 이유: 가중치+KV 캐시가 카드 메모리(48GB) 초과, 처리량 확장 필요
- 텐서 병렬: 모델을 카드에 분할 → **FXB 빌드 시(-tp) 고정**(커널이 병렬 크기 맞춰 컴파일)
- 파이프라인/데이터 병렬: FXB 재사용 가능, **서빙 시(-pp/-dp) 지정**

## Part C. NPU 실습환경 및 LLM 추론 실행 (모듈 3)

### C-1. 실습 전 환경 점검 절차
**문제** : RNGD 실습 전 환경 점검 절차를 순서대로 서술하고, 장치 미인식 시 대응을 쓰시오.

**채점 포인트**
- ① 드라이버 설치·재부팅 ② `furiosa-smi info`로 인식 확인 ③ `furiosa-smi status`로 점유·활용률 확인 ④ `furiosa-smi topo` ⑤ 패키지 설치·버전 확인 ⑥ HF_TOKEN 등 사전 준비
- 미인식 시: 드라이버 재설치/재부팅, `/dev/rngd` 권한, 컨테이너 시 `--device /dev/rngd` + `--security-opt seccomp=unconfined`

### C-2. furiosa-llm Python API 흐름
**문제** : furiosa-llm 오프라인 추론의 주요 구성 요소(클래스/메서드)를 나열하고, `generate`와 `stream_generate`의 차이를 설명하시오.

**채점 포인트**
- `LLM(model=...)` 모델 로드, `SamplingParams` 생성 옵션, `generate(prompts, params)` 배치 추론, `chat()` 채팅 템플릿 자동 적용
- `stream_generate`: 비동기 스트리밍, 토큰 생성 즉시 반환 → TTFT 체감·점진적 출력
- 실행 전후 `furiosa-smi status`로 NPU 활용률 상승 확인 가능

### C-3. OpenAI 호환 서버
**문제** : `furiosa-llm serve` 기동 방법, 제공 엔드포인트, 장점을 서술하시오.

**채점 포인트**
- 기동: `furiosa-llm serve <model-id> --devices npu:N --host --port`(기본 8000)
- 엔드포인트: `/v1/models`, `/v1/completions`, `/v1/chat/completions`(OpenAI 형식)
- 장점: 기존 OpenAI SDK/애플리케이션과 그대로 연동, 스트리밍 지원, (현재 1개 모델만 호스팅)

### C-4. 실습 오류 대응
**문제** : ①"장치 없음" ②"모델 다운로드 실패" ③"Device in use" ④"첫 실행 지연"의 원인과 대응을 쓰시오.

**채점 포인트**
- ① 드라이버/`/dev/rngd` 권한/컨테이너 디바이스 매핑 확인
- ② HF_TOKEN·라이선스 동의·네트워크 확인
- ③ `furiosa-smi ps`로 점유 프로세스 확인 후 빈 장치(`--devices npu:N`) 사용
- ④ 컴파일+가중치 다운로드로 수 분~수십 분 소요 → 이후 FXB 캐시로 단축(정상)

## Part D. 모니터링 및 성능지표 (모듈 4)

### D-1. 성능 지표 정의와 트레이드오프
**문제** : TTFT, TPOT, Throughput(토큰/s), 백분위 지연(p95/p99)을 정의하고 "낮은 지연↔높은 처리량" 트레이드오프를 서술하시오.

**채점 포인트**
- TTFT: 요청 후 첫 토큰까지 시간(사용자 체감 응답, Prefill 영향)
- TPOT: 출력 토큰 1개당 생성 시간(생성 속도, Decode 영향)
- Throughput: 초당 생성 토큰 수(서버 효율, 동시성과 비례)
- 백분위: p99 = 전체 요청 중 99%가 만족하는 지연 → 꼬리 사용자 품질
- 트레이드오프: 동시성↑ → 처리량·활용률↑ but 지연(TPOT/p99)↑ → SLO로 균형 관리

### D-2. furiosa-smi 상태 해석
**문제** : `furiosa-smi status`에서 코어 활용률 99%의 의미와, 활용률 30%인데 지연이 큰 경우의 해석을 각각 서술하시오.

**채점 포인트**
- 99%: NPU 최대 활용 → 연산량 위주 워크로드, 추가 부하 시 지연 급증 위험
- 30%+지연 큼: 병목이 NPU 밖 → 호스트 IO·전처리·워커 수·스케줄링·동시성 부족 점검, 벤치마크/프로파일로 구간 측정

### D-3. 벤치마크 절차
**문제** : furiosa-perf로 LLM 서빙 성능을 벤치마크하는 절차와 산출물을 서술하시오.

**채점 포인트**
- 절차: 서버 기동 → 시나리오(ISL/OSL/동시성 YAML) 실행 → HW 지표(전력·온도·활용률·호스트 CPU/메모리) 수집 → 정리
- 산출물: `summary_<ISL>_<OSL>.md/csv`, 시나리오별 `monitoring_log.csv`, HTML 보고서(TTFT/TPOT/토큰/s/TPS·Watt)

### D-4. 성능 개선 방안
**문제** : NPU 활용률은 높은데 p99 지연이 과도하다. 개선 방안을 3가지 이상 논리적으로 제시하시오.

**채점 포인트**
- ① 동시성/배치를 SLO 범위 내로 조정(지연-처리량 균형) ② INT8/FP8 정밀도 전환으로 연산·메모리 효율화 ③ 카드 추가/텐서 병렬로 용량 확장 ④ `max_model_len`·KV 캐시 예약 최적화 ⑤ 프로파일로 컴파일/스케줄 병목 확인

## Part E. K-FAST 파일럿 교육과정 활용 (모듈 5)

### E-1. 교육 설계
**문제** : 파일럿 교육(2~3일)에서 5개 모듈의 순서와 비율을 제시하고 그 근거를 서술하시오.

**채점 포인트**
- 순서: 1(이론)→2(하드웨어·SW)→3(실습:LLM 추론)→4(모니터링·성능)→5(활용·프로젝트) — 개념→구축→실행→분석→설계의 나선형
- 비율: 이론 35% / 실습 45% / 프로젝트 20%
- 근거: 실습 없이는 NPU 개념이 체화되지 않고, 성능 지표는 실행 후에 의미가 있기 때문

### E-2. 운영 리스크
**문제** : 파일럿 운영 시 리스크(NPU 자원 부족, 다운로드 지연, 실습 낙오 등) 3가지를 들고 각각의 대응을 서술하시오.

**채점 포인트**
- 자원 부족: 카드 공유·PE 분할, devices 할당표, 대기열 운영
- 다운로드/컴파일 지연: 사전 다운로드·FXB 캐시·예상 시간 명시
- 낙오자: T.A. 배치, 단계별 체크리스트·데드라인, 보충 영상 제공
- 네트워크/HF 이슈: 캐시 서버, 토큰 사전 발급
