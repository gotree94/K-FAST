# 강의안 작성 가이드 (강의 구성 및 실습 설계 평가 대비)

> **파일 경로** : `02_인증평가_대비/02_강의안_작성_가이드.md`
> **평가 항목** : 강의안 평가 — "강의 구성 및 실습 설계" 평가
> **평가 관점(예상)** : 학습 목표의 명확성, 내용의 체계성, 실습 설계의 타당성·실현 가능성,
> 시간 배분의 적절성, 학습자 수준 고려, 평가·피드백 연계 여부.

---

## 1. 강의안이 평가되는 핵심 기준

| 평가 기준 | 설명 | 좋은 예시 |
|-----------|------|-----------|
| 학습 목표 명확성 | 관찰 가능한 성과로 목표 제시 | "furiosa-llm으로 8B 모델을 서빙하고 curl로 응답을 받을 수 있다" |
| 내용 체계성 | 도입→전개→정리, 개념→실습 흐름 | "NPU 개념 → RNGD 구조 → 환경 점검 → 실행 → 모니터링" |
| 실습 설계 타당성 | 실습이 목표 달성에 직접 기여 | 목표와 실습(산출물)이 1:1 대응 |
| 시간 배분 | 단계별 예상 시간과 여유(버퍼) 확보 | 3시간 수업에 20% 버퍼 |
| 학습자 고려 | 수준별 대응, 사전 지식 안내 | 초급 보충 자료, 중급 심화 과제 명시 |
| 평가·피드백 연계 | 성취 확인 방법과 피드백 시점 | 단계별 체크리스트, 설문, 결과 해석 발표 |

---

## 2. 강의안 표준 템플릿 (작성 시 그대로 사용)

```markdown
# [모듈명] 강의안

## 1) 강의 개요
- 강의명 : (예) 모듈 3. NPU 실습환경 및 LLM 추론 실행
- 대상/수준 : (예) 대학원생·개발자 / 중급
- 시간 : 3시간 (이론 1h + 실습 2h)
- 사전 지식 : Python 기초, Linux 기본 명령어

## 2) 학습 목표 (3~5개, 행동 동사로)
1. furiosa-smi로 NPU 상태를 확인할 수 있다.
2. furiosa-llm Python API로 오프라인 추론을 실행할 수 있다.
3. OpenAI 호환 서버를 기동하고 호출할 수 있다.
4. 흔한 실습 오류를 해결할 수 있다.

## 3) 강의 흐름 (시간표)

| 시간 | 구간 | 내용 | 교수법 | 실습/산출물 |
|------|------|------|--------|-------------|
| 0:00–0:10 | 도입 | 학습 목표·실습 환경 소개 | 발표 | - |
| 0:10–0:40 | 이론 | NPU/추론 개념, RNGD 소개 | 설명+슬라이드 | 필기 |
| 0:40–1:10 | 실습1 | 환경 점검 (furiosa-smi) | 시연 후 개인 실습 | 점검 로그 |
| 1:10–1:40 | 실습2 | 오프라인 추론 실행 | 개인 실습 | 출력 결과 |
| 1:40–2:10 | 실습3 | 서버 기동·API 호출 | 개인 실습 | curl 응답 |
| 2:10–2:40 | 실습4 | 모니터링 관찰 (status) | 조별 관찰 | 실습일지 |
| 2:40–3:00 | 정리 | 오류 정리·Q&A·피드백 | 토론 | 설문 |

## 4) 교수 자료 및 도구
- 슬라이드 : 개념 10장 / 실습 스크린샷 5장
- 명령어 치트시트, 샘플 코드(furiosa-llm), 실습 체크리스트
- 장비 : RNGD 서버 1대 + 교육생 계정(devices 할당표)

## 5) 실습 설계 상세
- 실습 1 : [명령어] [예상 결과] [실패 시 대안]
- 실습 2 : [코드] [예상 결과] [실패 시 대안]
- ...
- (각 실습에 "성공 판정 기준"을 명시)

## 6) 평가 및 피드백
- 단계별 실습 체크리스트 배부 → 완료 시 확인 서명
- 종료 시 난이도/속도/재료 설문 → 다음 차시 반영
- 보충 과제 : [중급/상급용 심화 과제]

## 7) 리스크 및 대안
| 리스크 | 대안 |
|--------|------|
| NPU 점유 경합 | devices 할당표, 대기열 |
| 모델 다운로드 지연 | 사전 캐시/FXB 준비 |
| 실습 낙오 | T.A. 배치, 보충 영상 |
```

## 3. 좋은 강의안 vs 아쉬운 강의안 (비교)

| 구분 | 좋은 강의안 | 아쉬운 강의안 |
|------|-------------|----------------|
| 목표 | "생성 속도(TPOT)를 furiosa-perf로 측정해 해석할 수 있다" | "성능 지표를 이해한다" |
| 구성 | 도입 10% / 이론 30% / 실습 50% / 정리 10% | 이론 90% + 실습 1줄 언급 |
| 실습 | 명령어·예상 결과·성공 기준까지 명시 | "실습 진행"만 기술 |
| 시간 | 버퍼 포함, 단계별 시간 상세 | 총 시간만 명시 |
| 학습자 | 사전 지식·수준별 과제 명시 | 대상 명시 없음 |
| 리스크 | 장애 대안까지 기술 | 대안 없음 |

## 4. 실습 설계의 핵심 원칙 (평가 시 주목 포인트)

1. **목표-실습 일치** : 각 실습이 어떤 학습 목표를 검증하는지 명시.
2. **성공 판정 기준** : "어떤 결과가 나오면 성공"을 숫자/구체적으로 제시
   (예: "curl 응답에서 200 OK + JSON에 content 필드 확인").
3. **단계적 스캐폴딩** : 시연(Show) → 따라 하기(Do) → 변형 과제(Apply).
4. **오류 시나리오 포함** : 자주 발생하는 오류 3~5개와 대응을 사전 정리.
5. **모니터링/성과 관찰 포함** : NPU 활용률처럼 "하드웨어가 동작함을 보여주는" 지표 확인.
6. **산출물 명확화** : 실습일지·스크린샷·결과 파일 등 남길 것 정의.

## 5. 추천 작성 연습 과제

1. **모듈 3 기반** 3시간 강의안 (위 템플릿 사용) → 인증 평가용 1차 제출물.
2. **모듈 4 기반** 2시간 강의안 : TTFT/TPOT 정의 + furiosa-perf 실습 + 결과 해석.
3. **모듈 1 기반** 1시간 강의안 : NPU 개념 + 시연(양자화 효과) — 초급 대상.

> 팁 : 인증 평가에선 "하나의 강의안"을 요구하는 경우가 많으므로, 1번(모듈 3, 3시간)을
> 가장 완성도 높게 다듬고 나머지는 변형 대비용으로 준비하세요.

## 6. 자기 점검 체크리스트

- [ ] 학습 목표가 행동 동사 + 구체 산출물로 쓰였는가
- [ ] 시간표에 도입/이론/실습/정리가 모두 있고 합계가 정확한가
- [ ] 실습마다 명령어·예상 결과·성공 기준·실패 대안이 있는가
- [ ] 수준별(초/중/상) 대응이 명시되어 있는가
- [ ] 평가 방법과 피드백 시점이 있는가
- [ ] 리스크 표가 있는가
- [ ] 파일럿 교육(모듈 5)과 연결해 "왜 이 강의가 교육에 필요한지" 설명할 수 있는가
