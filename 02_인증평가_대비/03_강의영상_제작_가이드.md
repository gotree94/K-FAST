# 강의영상 제작 가이드 (5분 내외 / 전달력·실습 진행능력 평가 대비)

> **파일 경로** : `02_인증평가_대비/03_강의영상_제작_가이드.md`
> **평가 항목** : 강의영상 평가 — 5분 내외, 강의 전달력 및 실습 진행능력 평가
> **평가 관점(예상)** : 내용 전달의 명확성, 목소리·속도·시선 처리, 시연의 정확성·완결성,
> 실습 단계 설명력, 시간 준수, 전체적인 몰입도.

---

## 1. 5분 영상의 정석 구성 (시간 배분)

| 구간 | 시간 | 내용 | 비중 |
|------|------|------|------|
| 오프닝 | 0:00–0:15 | 자기소개(1문장) + 오늘 배울 것 1문장 | 5% |
| 이론 훑기 | 0:15–1:30 | 핵심 개념 1~2개를 "왜 필요한지" 중심으로 | 25% |
| 실습 시연 | 1:30–4:30 | 실제 명령 실행 + 결과 화면 + 해석 | 60% |
| 핵심 요약 | 4:30–4:50 | 배운 것 3줄 요약 + 다음으로 이어질 내용 | 7% |
| 마무리 | 4:50–5:00 | 질문 유도 / 강의 마무리 | 3% |

> **핵심** : 5분이면 **"이론 하나 + 실습 하나"** 를 깔끔하게 보여주는 것이 가장 안전합니다.
> 여러 주제를 넣으면 깊이가 떨어집니다.

---

## 2. 주제 선택 추천 (실습 시연이 잘 보이는 것)

1. **furiosa-llm으로 8B 모델 오프라인 추론 실행** — 코드 실행 + 출력 확인.
2. **furiosa-smi status로 NPU 활용률 관찰** — 실습 전/후 비교 화면.
3. **OpenAI 호환 서버 기동 + curl 호출** — 서버→응답까지 완결성 높음.
4. **furiosa-perf 벤치마크 + 결과 해석** — 지표(TTFT/TPOT) 시연.
5. **양자화(INT8) 전후 지연 비교 시연** — 개념+실습 연결이 좋음.

> 시연은 **반드시 미리 연습**하고, 화면이 커지지 않도록 터미널 글꼴/창 크기를 키워 촬영하세요.

---

## 3. 실습 진행(시연)이 잘 보이는 6가지 포인트

1. **화면 준비** : 터미널 글꼴 크게, 관련 없는 창 닫기, 명령어 미리 준비.
2. **타이핑 vs 붙여넣기** : 핵심 명령은 천천히 타이핑해 보여주고, 긴 코드는 미리 붙여 넣되 "지금 실행하는 부분이 무엇인지" 설명.
3. **단계 소리내기** : "1단계 환경 확인 → 2단계 모델 로드 → 3단계 실행"처럼 단계를 말로 안내.
4. **결과 강조** : 응답 출력, `furiosa-smi status`의 활용률 수치 등 **눈에 보이는 결과**를 포인터로 짚으며 설명.
5. **속도** : 실행 대기(컴파일 등) 시간은 컷. 결과 화면만 보여주고 "컴파일은 수 분 걸리지만 캐시로 빠릅니다"라고 설명.
6. **오류 처리 시연(선택)** : 자주 나는 오류 1개를 보여주고 해결 → 실습 진행능력 어필.

## 4. 전달력 향상 체크리스트

### 내용
- [ ] 오프닝에 "오늘의 목표 + 배울 이유"가 명확한가
- [ ] 전문 용어는 반드시 한 문장으로 풀어 설명했는가 (예: TTFT = "첫 답변까지 걸리는 시간")
- [ ] 슬라이드/화면 글자가 과하지 않은가 (7줄 이내 원칙)
- [ ] 실습과 이론이 연결되는지 ("방금 본 활용률이 의미하는 것은…") 말로 이어줬는가

### 화법·태도
- [ ] 목소리가 일정한 속도로 들리며 쉬는 시간이 있는가
- [ ] 시선이 화면 또는 카메라를 향하는가 (읽기만 하지 않는가)
- [ ] "아…", "음…" 같은 군더더기가 없는가
- [ ] "~입니다" 어미를 일관되게 사용했는가

### 실습 시연
- [ ] 시연 전에 예상 결과를 미리 말했는가 ("이렇게 하면 이런 결과가 나옵니다")
- [ ] 실행 결과를 해석하며 넘어갔는가 (결과만 보여주고 끝내지 않았는가)
- [ ] 시간 내 완결성 있게 마무리했는가

## 5. 5분 스크립트 예시 (주제: furiosa-llm 오프라인 추론)

```
[오프닝, 15초]
"안녕하세요, K-FAST 교육에 참여할 OOO입니다. 오늘은 Furiosa RNGD NPU에서
furiosa-llm을 이용해 8B 규모 LLM의 추론을 직접 실행해 보겠습니다."

[이론, 1분 15초]
"LLM 추론은 크게 두 단계로 나뉩니다. 첫 번째 Prefill은 프롬프트 전체를 한 번에
처리해서 KV 캐시를 만드는 단계이고, 두 번째 Decode는 토큰을 한 개씩 생성하는
단계입니다. furiosa-llm은 이 과정을 RNGD NPU에서 최적화해 실행해 주는
LLM 서빙 엔진입니다. vLLM과 호환되는 API를 제공하기 때문에 기존 코드를
그대로 옮겨 쓸 수 있다는 장점이 있습니다."

[실습 시연, 3분]
"먼저 환경을 확인하겠습니다. furiosa-smi status로 NPU가 인식됐는지 봅니다.
npu0에 8개 코어가 모두 유휴 상태입니다. 이제 Python에서 모델을 로드합니다.
(코드 입력) LLM 객체를 만들면 HF에서 사전 컴파일된 모델을 가져옵니다.
프롬프트를 준비하고 SamplingParams로 최대 생성 토큰을 설정합니다.
generate를 호출합니다. 이렇게 응답이 생성되는 것을 볼 수 있습니다.
실행 후 다시 furiosa-smi status를 보면 코어 활용률이 99%까지 올라갔습니다.
즉, NPU가 실제로 연산에 사용되고 있다는 뜻입니다."

[요약, 30초]
"오늘은 세 가지를 확인했습니다. 첫째, LLM 추론은 Prefill과 Decode로 나뉘고,
둘째, furiosa-llm의 vLLM 호환 API로 모델을 실행할 수 있고,
셋째, furiosa-smi로 NPU 활용 여부를 확인할 수 있다는 점입니다.
다음 시간에는 이 실행 결과를 바탕으로 성능 지표를 측정해 보겠습니다."

[마무리, 15초]
"여기까지 질문이 있다면 댓글로 남겨 주세요. 시청해 주셔서 감사합니다."
```

## 7. 평가자 관점에서 자주 지적되는 감점 요소

- 5분을 크게 초과 (편집으로 반드시 5분 내외 맞출 것)
- 시연 없이 슬라이드 나열만
- 명령 실행 중 오류를 그대로 방치(해결하지 않고 넘어감)
- 결과를 보여주기만 하고 해석 없이 다음으로
- 목소리 단조로움 / 화면을 읽기만 함
- 기술 용어를 설명 없이 사용
- 시연 화면 글자가 너무 작음

## 8. 자기 점검 (촬영 후)

- [ ] 5분 ±30초 내에 완결되는가
- [ ] 오프닝 15초 안에 목표가 드러나는가
- [ ] 시연(실습)이 영상의 절반 이상인가
- [ ] 결과 화면을 해석하며 넘어갔는가
- [ ] 오류(있다면)를 해결하고 설명했는가
- [ ] 요약 3줄과 다음 내용 안내가 있는가
