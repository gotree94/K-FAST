# 모듈 5. K-FAST 파일럿 교육과정 활용 방안

> **파일 경로** : `01_교육내용_준비자료/05_KFAST_파일럿_교육과정_활용방안.md`
> **성격** : 교육 설계/운영. 앞선 4개 모듈을 K-FAST 파일럿 교육과정으로 어떻게 엮어 운영할지 설계하는 모듈.
> **예상 시수** : 이론 1.5시간 + 토론 1시간

---

## 1. 학습 목표

1. K-FAST 교육의 목적·대상·목표를 설정할 수 있다.
2. 5개 모듈을 학습자 수준에 맞게 편성한 커리큘럼(일정표)을 설계할 수 있다.
3. 이론/실습 비중, 평가·피드백 방식, 운영 리스크(자원·인원·환경)를 계획할 수 있다.
4. 산업/연구 현장 수요(LLM 서빙, RNGD 활용)를 교육 목표에 반영할 수 있다.
5. 교육 성과 측정(수료 기준, 만족도, 취업/활용 연계) 방안을 제시할 수 있다.

---

## 2. 교육 설계 방향

### 2.1 교육 목적 (안)

- **국내 AI 반도체(NPU) 생태계 인력 양성** : Furiosa RNGD를 실제로 다룰 수 있는 실무형 인재 배출.
- **LLM 서빙 실무 역량** : 추론 환경 구축·실행·모니터링·성능 분석까지 원스톱 체험.
- **파일럿 운영** : 본 교육 확대 전 소규모(예: 20~30명) 파일럿으로 교재·실습 검증.

### 2.2 대상 및 사전 지식 (안)

| 구분 | 내용 |
|------|------|
| 대상 (안) | 대학(원)생, 취업준비생, 현업 개발자·엔지니어, 연구원 |
| 사전 지식 | Python 기초, 딥러닝 기초 개념(선택), Linux 명령어 기초(권장) |
| 사전 과제 | Linux/SSH 접속, Python 환경 세팅, HF 계정·HF_TOKEN 준비 |

### 2.3 학습자 수준별 대응

| 수준 | 대응 전략 |
|------|-----------|
| 하(이론 기초 부족) | 모듈 1을 충분히 배정, 보충 개념(딥러닝 기초) 제공 |
| 중(실습 경험 있음) | 모듈 3·4 실습 심화 과제로 배치·모니터링 분석 강화 |
| 상(LLM 서빙 경험) | vLLM 이식, 멀티카드(텐서 병렬), 성능 최적화·튜닝 프로젝트 부여 |

## 3. 파일럿 커리큘럼 예시

> 2일(집중) ~ 3일(완화) 과정 기준. 실습은 강사 시연 → 개인 실습 → 조별 프로젝트 순.

### 3.2 3일 완화 과정 (안) — 실습 비중 확대

- 1일차 : 모듈 1 + 모듈 2 (이론 집중, RNGD 사양·SW 스택 암기 포인트)
- 2일차 : 모듈 3 실습 (환경 → 8B LLM 서빙 → OpenAI API)
- 3일차 : 모듈 4 벤치마크/모니터링 + 모듈 5 프로젝트·발표·평가

### 3.3 이론/실습 비율 권장

- 파일럿 : **이론 35% / 실습 45% / 프로젝트·발표 20%**
- 실습 중 사고 시나리오(장애 복구, 리소스 부족)를 사전에 준비.

## 4. 교수법 및 운영 전략

1. **시연 우선 방식 (Show→Do)** : 강사가 먼저 실행 결과를 보여준 뒤 학습자가 따라 하는 단계적 실습.
2. **스캐폴딩 실습지** : 단계별 체크리스트(무엇을·어떻게·어떤 결과가 나와야 하는지)를 사전 배포.
3. **실시간 모니터링 연동** : 학습자별 `furiosa-smi status` 화면을 공유하며 활용률 변화를 설명.
4. **페어 프로그래밍** : 2인 1조로 한 카드를 나눠 쓰며 오류 해결 협업 유도.
5. **산출물 기반 평가** : 실습일지(명령어·결과·해석) + 조별 서빙 프로젝트 + 발표.
6. **피드백 루프** : 매일 설문(난이도·속도·실습 재료)으로 다음 날 조정.

---

## 5. 평가 설계 (파일럿)

| 평가 | 대상 | 방법 | 비중(안) |
|------|------|------|----------|
| 이해도 평가 | 개인 | 서술형 시험(개념·사양·지표) | 30% |
| 실습 수행 | 개인 | 실습 과제 완료·정확성·오류 대응 | 40% |
| 프로젝트 | 조 | 모델 서빙 + 벤치마크 + SLO 제안 발표 | 30% |
| 수료 기준 (안) | - | 총점 60점 이상 + 핵심 실습 3개 이상 완료 | - |

## 6. 운영 고려사항 및 리스크

| 리스크 | 대응 |
|--------|------|
| NPU 자원 부족(인원≫카드) | 카드 공유/PE 분할, 사전 할당표(devices) 작성, 대기열 운영 |
| 모델 다운로드 과부하(네트워크) | 실습 전 캐시 서버·사전 다운로드 이미지 준비 |
| HF 토큰/라이선스 이슈 | 사전 동의 절차, 교육용 계정 일괄 발급 |
| 첫 컴파일 시간 지연 | 사전 컴파일된 FXB 모델만 사용, 교재에 예상 소요 명시 |
| 실습 낙오자 발생 | 조교(T.A.) 배치, 단계별 데드라인, 사후 보충 영상 제공 |
| 보안(서버 공유) | 사용자 격리(컨테이너), 세션 타임아웃, 자원 사용 정책 |

---

## 7. 산업/연구 활용 연계 (파일럿 성과 확장)

- **취업 연계** : AI 반도체 기업(FuriosaAI 등)·데이터센터·서빙 스타트업 대상 수료생 추천 채널.
- **연구 연계** : NPU 추론 최적화, 벤치마크 방법론, 에너지 효율 분석 등 산학 프로젝트 주제 제안.
- **커리큘럼 업데이트** : 모델·소프트웨어 버전 변화를 반영한 연 2회 개정 사이클.
- **성과 지표** : 수료율, 취업/전공 연계율, 만족도, 후속 과정 신청률.

---

## 8. 핵심 포인트 요약

- K-FAST 교육의 가치는 "RNGD로 실제 LLM을 서빙·모니터링·최적화할 수 있는 실무 역량"을 주는 것.
- 이론(1·2) → 실습(3·4) → 설계·프로젝트(5)의 나선형 구성.
- 실습 자원(카드·네트워크·모델) 사전 확보가 파일럿 성공의 관건.
- 성과는 "수료"가 아니라 "활용(취업·연구·후속과정)"으로 측정.

---

## 9. 예상 Q&A

- **Q. 파일럿 인원은 몇 명이 적절한가요?** → A. 카드당 실습 시간과 인원에 따라 다르지만, 1인 1카드 기준 8~20명, 공유 기준 최대 30명 내외가 관리 가능합니다.
- **Q. 학습자가 GPU 경험만 있는 경우?** → A. 개념(모듈 1)은 유사하므로 빠르게 넘어가고, NPU 고유 부분(컴파일러·FXB·furiosa-smi)에 집중하도록 커리큘럼을 조정합니다.
- **Q. 교육이 끝난 뒤도 실습 환경을 쓸 수 있나요?** → A. 운영 정책에 따라 다르며, 후속 과정·과제 수행을 위해 일정 기간 접근 권한을 유지하는 방안을 제안합니다.
