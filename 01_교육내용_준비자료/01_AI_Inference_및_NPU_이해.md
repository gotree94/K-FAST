## 2. 핵심 개념 (강의 초반에 반드시 다룰 개념)

| 개념 | 한 줄 정의 |
|------|-----------|
| Inference | 학습된 모델 가중치로 새 입력에 대한 출력을 예측하는 과정 |
| Tensor Contraction | 텐서들 사이의 곱·합(예: 행렬 곱, 합성곱) — 딥러닝 연산의 근간 |
| NPU | 딥러닝 추론(또는 학습)을 위해 최적화된 신경망 전용 반도체 |
| TOPS / TFLOPS | 초당 정수 연산(조 단위) / 초당 부동소수점 연산(조 단위) |
| Compute-bound | 연산량이 병목인 경우 (계산 능력이 성능 결정) |
| Memory-bound | 데이터 이동(대역폭)이 병목인 경우 (메모리가 성능 결정) |
| Quantization | FP32→INT8·FP8 등 낮은 정밀도로 변환해 연산·메모리를 줄이는 기법 |
| LLM 추론 | 생성형 대규모 언어모델을 입력 프롬프트에 대해 토큰 단위로 생성하는 서빙 작업 |

## 3. 상세 내용

### 3.1 AI 추론의 개념과 특성

- **학습(Training)** : 대량 데이터를 이용해 가중치를 갱신. 순전파+역전파 반복, 연산량이 크고 정밀도(FP32/BF16)가 중요.
- **추론(Inference)** : 학습이 끝난 고정 가중치로 한 번만 순전파. **지연시간(Latency)** 과 **처리량(Throughput)**, **전력 효율**이 중요.
- 온보딩 교육은 "서빙/배포" 관점이므로 추론에 집중해야 함.

**추론 워크로드의 특성**
- 행렬 곱·텐서 축약이 대부분의 연산 시간을 차지 → 병렬 연산 최적화가 중요
- 입력 데이터의 **재사용성이 높음** → 온칩 SRAM에 데이터를 올려 두면 DRAM 접근 횟수 감소
- 실시간 응답이 요구되는 경우 많음 → 낮은 지연시간이 중요
- 동일 모델을 수많은 요청이 반복 수행 → 처리량(QPS, tokens/s) 최적화 필요

### 3.2 하드웨어 가속기 비교 (CPU / GPU / NPU)

| 구분 | CPU | GPU | NPU |
|------|-----|-----|-----|
| 설계 목적 | 범용 연산·제어 | 병렬 부동소수점 연산 | 딥러닝 연산(추론) 특화 |
| 핵심 장점 | 유연성, 낮은 지연 | 높은 병렬 처리량 | 최고의 전력 효율/단위면적 성능 |
| 단점 | 딥러닝 처리량 낮음 | 전력 소모 큼 | 유연성 낮음 |
| 전형적 용도 | 호스트 제어, 데이터 전처리 | 학습, 대형 서빙 | 에지/데이터센터 추론 서빙 |

**성능 단위 설명**
- `TOPS (Tera Operations Per Second)` : 초당 **정수** 연산 횟수(10^12). NPU·양자화 모델의 성능 척도로 사용.
- `TFLOPS (Tera Floating-point Operations Per Second)` : 초당 **부동소수점** 연산 횟수. GPU·BF16/FP8 모델 성능 척도.
- 동일 칩이라도 **정밀도가 낮을수록** 단위 시간당 처리 가능한 연산 수가 커짐 (예: INT8 2배, INT4 4배 vs FP32 수준).
- 부수 지표 : 메모리 용량(GB), 메모리 대역폭(TB/s), TDP(W), 활용률(%), 지연시간(ms), 처리량(tokens/s, QPS).

### 3.3 NPU 아키텍처 핵심 요소

1. **PE (Processing Element, 연산 유닛)**
   - MAC(곱셈-누적) 배열로 구성. 행렬 곱 등 텐서 축약을 고속 수행.
   - NPU마다 PE 개수·구성이 다르며, PE 간 병렬로 워크로드를 분산.
2. **온칩 SRAM (On-chip SRAM)**
   - 가중치·중간 결과를 저장하는 고속 버퍼. 접근 대역폭이 외장 메모리보다 수백 배 큼.
   - "가중치 재사용 + SRAM 적재"가 NPU 성능의 핵심 원리.
   - 예: RNGD는 256MB SRAM, 온칩 대역폭 약 384TB/s.
3. **외장 메모리 (HBM/DRAM)**
   - 모델 전체(가중치·KV 캐시 등)를 담는 대용량 저장소.
   - 예: RNGD는 HBM3 48GB, 대역폭 1.5TB/s.
   - 용량이 부족하면 모델이 여러 카드에 분산(텐서 병렬)되어야 함.
4. **내부 네트워크 / 인터커넥트**
   - PE↔SRAM↔메모리 사이 데이터 이동 경로(NoC).
   - 칩 간 통신은 PCIe 기반 (RNGD는 PCIe Gen5 x16).
   - NPU 활용률이 낮은 가장 흔한 원인 중 하나가 "데이터 이동 병목".
5. **호스트 인터페이스(PCIe)**
   - CPU 호스트와 데이터 주고받는 경로. 대역폭이 좁으면 IO 바운드 발생.

> **교수 포인트** : "NPU는 연산 뿐 아니라 **데이터 이동을 줄이는 구조**가 성능을 좌우한다"는 메시지를 전달. SRAM 재사용 → HBM 접근 최소화 → 최고 효율.

### 3.4 컴퓨트 바운드 vs 메모리 바운드

- **컴퓨트 바운드** : 연산 유닛이 계속 바쁘게 일하고 있음 → 활용률 높음. 연산 성능을 높이면 빨라짐.
- **메모리 바운드** : 연산 유닛이 데이터 기다리며 놂 → 활용률 낮음. 대역폭·데이터 재사용을 늘리면 빨라짐.
- 판별법 : 실행 프로파일에서 NPU 실행 시간 vs 데이터 이동(IO wait) 시간을 비교.
- 대표 사례 : GPT 계열 등 디코드 단계는 메모리 바운드에 가까움(KV 캐시 재사용 제약) → 때문에 PagedAttention·연속 배치 같은 메모리 최적화가 중요.

### 3.5 양자화(Quantization) 이해

- 정의 : 실수 가중치/활성화를 INT8·INT4·FP8 등 낮은 정밀도로 변환.
- 효과 : ① 연산 속도 증가(정밀도가 낮을수록 TOPS 상승) ② 메모리 사용량 감소 ③ 대역폭 절감.
- 부작용 : 정밀도 손실 → 정확도 저하 가능. 학습 후 양자화(PTQ)·양자화 인식 학습(QAT)으로 보완.
- **정밀도별 성능 예시(RNGD)** :

| 정밀도 | 성능 |
|--------|------|
| BF16 | 256 TFLOPS |
| FP8 | 512 TFLOPS |
| INT8 | 512 TOPS |
| INT4 | 1,024 TOPS |

- 실제 서빙에서는 FP8/INT8을 주로 사용 → 메모리 요구량 절반 이하로 감소.

### 3.6 LLM 추론 개요 (모듈 3·4의 기초)

- **Tokenizer** : 텍스트를 토큰 단위로 변환.
- **Prefill(전치리) 단계** : 전체 프롬프트를 한 번에 처리해 KV 캐시 생성. 연산량 큼 → 컴퓨트 바운드 경향.
- **Decode(디코드) 단계** : 토큰을 한 개씩 생성, 매 단계 직전까지의 KV 캐시를 재사용. 대역폭 소모 큼 → 메모리 바운드 경향.
- **KV Cache** : 이전 토큰들의 Key/Value 벡터를 저장해 중복 연산 방지. 모델이 크고 시퀀스가 길수록 많은 메모리 소모.
- **성능 지표 미리보기** :
  - TTFT(Time To First Token) : 요청 후 첫 토큰까지 시간 → 사용자 체감 응답.
  - TPOT(Time Per Output Token) : 출력 토큰 1개당 생성 시간 → 생성 속도 체감.
  - Throughput : 초당 처리 토큰 수(tokens/s) → 서버 효율.
- **서빙 최적화 기법 소개** : 연속 배치(Continuous Batching), PagedAttention, 텐서 병렬(Tensor Parallel) 등 (모듈 2·3에서 상세).

## 5. 핵심 포인트 요약

- 추론은 학습과 달리 **지연시간·처리량·전력 효율**이 핵심 성능 지표다.
- 딥러닝 연산의 본질은 **텐서 축약(행렬 곱)** 이며, NPU는 이를 전용 하드웨어로 가속한다.
- NPU 성능 = 연산 능력(TOPS) × **데이터 재사용(SRAM)** × 메모리 대역폭.
- 낮은 정밀도(INT8/FP8/INT4)는 속도·메모리를 높이되 정확도 손실을 관리해야 한다.
- LLM 추론은 Prefill(연산 집중)과 Decode(메모리 집중)로 나뉘며, 성능 지표로 TTFT·TPOT·tokens/s를 사용한다.

## 6. 예상 Q&A (학습자 질문 대비)

- **Q. NPU가 GPU보다 항상 빠른가요?** → A. 아닙니다. 동일 연산을 전용 하드웨어로 처리해 **단위 전력·단위 면적당 효율**이 높을 뿐, 특정 워크로드(학습, 비정형 연산)는 GPU가 유리합니다. 워크로드 특성에 맞는 가속기를 선택하는 것이 중요합니다.
- **Q. 왜 온칩 SRAM이 중요한가요?** → A. 외장 HBM보다 접근 대역폭이 수백 배 커서, 가중치를 SRAM에 올려 재사용하면 메모리 병목을 크게 줄일 수 있기 때문입니다. 데이터 이동을 줄이는 것이 NPU 성능의 핵심입니다.
- **Q. FP32 모델을 그대로 돌려도 되나요?** → A. 실행은 가능하지만 NPU의 강점(저정밀 고속 연산)을 활용하지 못합니다. 추론 전용으로 양자화(INT8/FP8)를 수행하는 것이 일반적입니다.
- **Q. LLM이 느린 이유는 무엇인가요?** → A. 생성 방식이 순차적(토큰 1개씩)이기 때문입니다. 디코드 단계는 KV 캐시를 읽는 메모리 대역폭이 병목이 되는 경우가 많아, 배치·캐시 최적화가 중요합니다.
